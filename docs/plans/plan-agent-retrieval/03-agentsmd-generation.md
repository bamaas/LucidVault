# Sub-plan 03: AGENTS.md Generation

## Goal

Create `internal/agentsmd/` package that generates and maintains `AGENTS.md` in the vault root. Static template with vault access rules + dynamic sections for MCP tool listing and vault stats.

## Dependencies

- Sub-plan 02 (vault_overview logic for stats; all MCP tools registered for introspection).

## Context

### Design from plan

- **Static sections** (hand-authored template): Vault Access Rules, Retrieval Strategy, Content Guidelines.
- **Dynamic sections** (generated at runtime): Available MCP Tools (introspected), Vault Stats (counts, tags).
- Written to `{vaultPath}/AGENTS.md` on startup and each poll cycle.
- Idempotent — only writes if content changed (content-hash comparison).
- Package: `internal/agentsmd/`

### MCP tool introspection

`mcp-go` SDK: `server.MCPServer` doesn't expose a public method to list registered tools. Options:

1. Maintain a parallel tool registry in LucidVault code (list of tool name + description structs).
2. Use the MCP server's `ListTools` capability via internal call.

Approach: maintain a `ToolInfo` slice built during `registerTools`. Each entry has Name, Description, Parameters. Pass this to AGENTS.md generator.

### Integration points

- **`cmd/main.go`** — Call `agentsmd.Generate(...)` on startup and in `runPollCycle`.
- **`internal/mcpserver/server.go`** — Export tool metadata during registration.

### Vault methods available

- `v.WriteFile(relPath, content)` — doesn't exist yet; use `os.WriteFile` directly or add a method.
- Actually, `AGENTS.md` goes in vault root. Can use `v.ReadFile("AGENTS.md")` for reading and write via `os.WriteFile(filepath.Join(v.BasePath(), "AGENTS.md"), ...)`.
- `v.ScanWikiDir()`, `v.ScanRawDir()` for counts.
- `v.ReadIndex()` for tag extraction.
- `v.FileExists(relPath)` for soul.md check.

package agentsmd

// ToolInfo describes an MCP tool for AGENTS.md documentation.

### 2. Create static template

File: `internal/agentsmd/template.md` (embedded via `//go:embed`)

Content (hand-authored vault instructions for agents):

```markdown
# AGENTS.md — Vault Instructions for AI Agents

This file is auto-generated by LucidVault. Do not edit manually.

## Vault Access Rules

- **Read directly**: wiki/, raw/, notes/, index.md, soul.md, AGENTS.md
- **Write through MCP only**: Use MCP tools for all mutations (add_bookmark, add_note, update_wiki, delete_page)
- **Never write files directly** — vault files have strict formatting requirements enforced by the MCP server

## Retrieval Strategy

1. Read `index.md` for topic discovery (slug, title, tags for every page)
2. Search `wiki/` first — these are LLM-enriched summaries, preferred for most queries
3. Check `notes/` for personal notes if wiki pages don't fully answer
4. Read `raw/` only when wiki summary lacks detail — raw files can be very large
5. Use `expand_graph` to discover related content clusters
6. Follow `[[wikilinks]]` in wiki pages to explore connections
7. Use `related_notes` for bidirectional link discovery

## Content Guidelines

- Prefer wiki/ pages over raw/ — wiki pages are concise summaries
- Read first 200 lines of raw/ files, not full content (they can be very large)
- When citing information, reference the wiki page slug
- soul.md describes the vault owner — read it for personalization context
```
